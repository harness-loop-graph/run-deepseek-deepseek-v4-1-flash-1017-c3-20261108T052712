# Architecture — Medical Appointments & Clinical History

This document is the implementation map for the fixed specification in
`SPEC.md`. It records the entity model, the endpoint-to-screen contract, and
the repository layout. Where this document and `SPEC.md` disagree, `SPEC.md`
wins.

## 1. System shape

```
browser ──HTTP──> frontend (React SPA, :8080, static)
                        │  fetch/JSON + Bearer access token
                        ▼
                  backend (NestJS REST, :3000)
                        │  pg (pool), SQL only, no ORM sync
                        ▼
                  db (PostgreSQL 16, :5432)
```

- Three Compose services: `db`, `backend`, `frontend`. Backend waits for the
  database, then runs migrations and the idempotent seed before listening.
- The SPA is a static build served by nginx. All state comes from the REST API;
  there is no server-side rendering and no backend session cookie.
- Authentication is OAuth 2.0 authorization-code + PKCE (S256). The
  authorization endpoint and the login form are served by the backend, the
  redirect target lives in the SPA (`http://localhost:8080/auth/callback`).
- Only one OAuth client is registered: `client_id=medapp-spa`,
  `redirect_uri=http://localhost:8080/auth/callback`.

## 2. Entity model

All tables live in the `public` schema. Every id is an integer assigned in
insertion order (`GENERATED BY DEFAULT AS IDENTITY`), so the deterministic
seed yields patients 1..3 and professionals 1..2.

### 2.1 `rol`

| Column | Type | Constraints |
| --- | --- | --- |
| `id` | integer | PK, identity |
| `nombre` | text | NOT NULL, UNIQUE, CHECK in `('patient','professional','staff','admin')` |

Seeded once, by name, idempotently (`ON CONFLICT (nombre) DO NOTHING`).

### 2.2 `usuario`

| Column | Type | Constraints |
| --- | --- | --- |
| `id` | integer | PK, identity |
| `email` | text | NOT NULL, UNIQUE (case-insensitive unique index on `lower(email)`) |
| `password_hash` | text | NOT NULL (scrypt/argon2 hash, never plaintext) |
| `activo` | boolean | NOT NULL DEFAULT true |
| `creado_en` | timestamptz | NOT NULL DEFAULT now() |

Index: unique on `lower(email)` for login lookup; index on `activo`.

### 2.3 `usuario_rol` (join table for the many-to-many roles)

| Column | Type | Constraints |
| --- | --- | --- |
| `usuario_id` | integer | NOT NULL, FK → `usuario(id)` ON DELETE CASCADE |
| `rol_id` | integer | NOT NULL, FK → `rol(id)` ON DELETE RESTRICT |
| PK | (`usuario_id`,`rol_id`) | composite primary key |

Index on `rol_id` (role filtering for EP-15).

### 2.4 `paciente`

| Column | Type | Constraints |
| --- | --- | --- |
| `id` | integer | PK, identity |
| `usuario_id` | integer | NOT NULL, UNIQUE, FK → `usuario(id)` |
| `nombre` | text | NOT NULL |
| `apellidos` | text | NOT NULL |
| `documento` | text | NOT NULL, UNIQUE |
| `fecha_nacimiento` | date | NOT NULL |

### 2.5 `profesional`

| Column | Type | Constraints |
| --- | --- | --- |
| `id` | integer | PK, identity |
| `usuario_id` | integer | NOT NULL, UNIQUE, FK → `usuario(id)` |
| `nombre` | text | NOT NULL |
| `apellidos` | text | NOT NULL (surname appears in the SCR-03 `<select>` label) |
| `especialidad` | text | NOT NULL |

### 2.6 `disponibilidad`

| Column | Type | Constraints |
| --- | --- | --- |
| `id` | integer | PK, identity |
| `profesional_id` | integer | NOT NULL, FK → `profesional(id)` |
| `franja_inicio` | timestamptz | NOT NULL |
| `franja_fin` | timestamptz | NOT NULL, CHECK `franja_fin > franja_inicio` |

Unique (`profesional_id`, `franja_inicio`); index on
(`profesional_id`, `franja_inicio`) for EP-06 range scans. Seeded as
weekday 08:00–16:00, 30-minute slots for the 14 days after deployment;
`lopez` (professional 2) has no Friday slots.

### 2.7 `cita`

| Column | Type | Constraints |
| --- | --- | --- |
| `id` | integer | PK, identity |
| `paciente_id` | integer | NOT NULL, FK → `paciente(id)` |
| `profesional_id` | integer | NOT NULL, FK → `profesional(id)` |
| `franja_inicio` | timestamptz | NOT NULL |
| `franja_fin` | timestamptz | NOT NULL, CHECK `franja_fin > franja_inicio` |
| `estado` | text | NOT NULL DEFAULT `'scheduled'`, CHECK in `('scheduled','attended','cancelled','no_show')` |
| `creada_en` | timestamptz | NOT NULL DEFAULT now() |
| `actualizada_en` | timestamptz | NOT NULL DEFAULT now() |
| `cancelada_en` | timestamptz | NULL |

Integrity and indexes (RF-03, RF-04, RF-13):

- Partial unique index `cita_slot_activo_uq` on
  (`profesional_id`, `franja_inicio`) `WHERE estado <> 'cancelled'` — one
  active booking per slot; cancelling frees the slot again.
- Index on (`paciente_id`, `franja_inicio`) for EP-05.
- Index on (`profesional_id`, `franja_inicio`, `estado`) for EP-09.
- Index on `estado`.

### 2.8 `encuentro` (append-only)

| Column | Type | Constraints |
| --- | --- | --- |
| `id` | integer | PK, identity |
| `cita_id` | integer | NOT NULL, FK → `cita(id)` |
| `version` | integer | NOT NULL, CHECK `version > 0` |
| `notas` | text | NOT NULL |
| `diagnostico` | text | NOT NULL |
| `autor_profesional_id` | integer | NOT NULL, FK → `profesional(id)` |
| `reemplaza_a_id` | integer | NULL, FK → `encuentro(id)` |
| `creado_en` | timestamptz | NOT NULL DEFAULT now() |

Unique (`cita_id`, `version`); index on (`cita_id`, `version DESC`) for the
EP-12 chronology. A correction inserts a new row with `version = previous + 1`
and `reemplaza_a_id = previous.id`; nothing is ever updated or deleted
(trigger below).

### 2.9 `adjunto`

| Column | Type | Constraints |
| --- | --- | --- |
| `id` | integer | PK, identity |
| `encuentro_id` | integer | NOT NULL, FK → `encuentro(id)` |
| `nombre_original` | text | NOT NULL (display only, escaped) |
| `nombre_almacenado` | text | NOT NULL, UNIQUE (server-generated, sanitized, no path separators) |
| `mime_type` | text | NOT NULL, CHECK in `('application/pdf','image/jpeg','image/png')` |
| `tamano_bytes` | integer | NOT NULL, CHECK `> 0 AND <= 5242880` |
| `subido_por` | integer | NOT NULL, FK → `profesional(id)` |
| `creado_en` | timestamptz | NOT NULL DEFAULT now() |

Index on `encuentro_id`. Bytes are stored on a backend volume outside any
publicly served directory; only EP-14 streams them, after a permission check.

### 2.10 `auditoria` (append-only)

| Column | Type | Constraints |
| --- | --- | --- |
| `id` | integer | PK, identity |
| `usuario_id` | integer | NOT NULL, FK → `usuario(id)` |
| `accion` | text | NOT NULL (e.g. `appointment.create`, `encounter.read`) |
| `recurso_tipo` | text | NOT NULL |
| `recurso_id` | integer | NULL |
| `ocurrido_en` | timestamptz | NOT NULL DEFAULT now() |
| `metadatos` | jsonb | NOT NULL DEFAULT `'{}'` (no clinical content, no secrets) |

Indexes on (`usuario_id`, `ocurrido_en`), `accion`, and `ocurrido_en` to
serve EP-19 filters `actor`, `action`, `from`, `to`.

### 2.11 Append-only enforcement (RF-06)

A `BEFORE UPDATE OR DELETE` trigger (`fn_append_only`) raises an exception on
`encuentro` and `auditoria`; `DELETE`/`UPDATE` are additionally not granted to
the application role. Corrections are new rows only.

### 2.12 Migrations and seed

- `backend/src/database/migrations/` holds ordered, versioned SQL migrations
  (`NNN_name.up.sql` / `NNN_name.down.sql`), applied inside a transaction and
  recorded in `schema_migrations(version, applied_at)`. The runner executes on
  backend start; `npm run migrate:down` applies the paired down scripts.
- `backend/src/database/seed/` inserts roles, users, patients, professionals
  and availability. Every statement is idempotent (`ON CONFLICT DO NOTHING` on
  natural keys), so repeated starts produce the same rows and ids.

## 3. Endpoint-to-screen contract

### 3.1 Endpoint catalog, guards and consumers

| ID | Verb & path | Guard / scope (server-side) | Screen(s) | Notes |
| --- | --- | --- | --- | --- |
| EP-01 | GET `/auth/authorize` | public, rate-limited 5/min/IP | SCR-01 | Validates `client_id`/`redirect_uri`, stores the PKCE challenge, 302 to the HTML login form |
| EP-02 | POST `/auth/token` | public, rate-limited 5/min/IP | SCR-01 (callback) | `{code, code_verifier, client_id, redirect_uri}` → `access_token`, `refresh_token` |
| EP-03 | POST `/auth/token/refresh` | refresh token | SCR-01 / any screen | 401 on expired or revoked |
| EP-04 | POST `/auth/revoke` | bearer or refresh token | SCR-01 (logout) | 204; revocation is immediate |
| EP-05 | GET `/me/appointments` | `patient` | SCR-02 | Own appointments only (`paciente_id = session`) |
| EP-06 | GET `/availability` | `patient` | SCR-03 | `professionalId`, `from`, `to` (`YYYY-MM-DD`); 200 `[{start,end}]`; 422 invalid range; excludes booked/cancelled-slot logic |
| EP-07 | POST `/appointments` | `patient` | SCR-03 | `{professionalId, slotStart}`; 201 `{id}`; 409 on taken slot; 10/min/user; transactional |
| EP-08 | DELETE `/appointments/:id` | `patient`, own only | SCR-02 | 204; 403 not own; 404 unknown; frees the slot |
| EP-09 | GET `/agenda` | `professional` | SCR-04 | `from`, `to`; 200 grouped by day; SCR-04 defaults to today..+7 days |
| EP-10 | GET `/appointments/:id` | `patient` own or assigned `professional` | SCR-05 | 200/403/404 |
| EP-11 | POST `/appointments/:id/encounter` | assigned `professional` | SCR-05 | `{notes, diagnosis}`; 201 encounter; 403 not assigned |
| EP-12 | GET `/patients/:id/clinical-history` | `patient` self or assigned `professional` | SCR-06 | Chronology with attachments; 403 otherwise |
| EP-13 | POST `/encounters/:id/attachments` | author `professional` | SCR-05 / SCR-06 | multipart; 413 >5 MB; 415 bad type; 422 validation |
| EP-14 | GET `/attachments/:id` | author `professional` or owning `patient` | SCR-06 | 200 stream; 403/404; audit the read |
| EP-15 | GET `/admin/users` | `admin` | SCR-07 | `page`; paginated |
| EP-16 | POST `/admin/users` | `admin` | SCR-07 | `{email, roles}`; 201; 409 exists; 422 |
| EP-17 | PATCH `/admin/users/:id/roles` | `admin` | SCR-07 | `{roles}`; 200; 422 unknown role |
| EP-18 | PUT `/admin/professionals/:id/availability` | `admin` | SCR-07 | `{slots:[{start,end}]}`; 200 replaces set; 422 overlap |
| EP-19 | GET `/admin/audit` | `admin` | SCR-08 | `actor`, `action`, `from`, `to`; paginated |
| EP-20 | GET `/health` | public | — | 200 `{status:"ok"}`; Compose healthcheck |

`staff` consumes EP-09 (agenda) and EP-06-style scheduling reads; it never has
an allowed path to EP-11..EP-14 (clinical content), and `nav-history` is not
rendered for it.

Navigation visibility (RF-20), rendered by `routes/ProtectedRoute.tsx` and the
shell:

| Role | `nav-*` items |
| --- | --- |
| `patient` | `nav-bookings` (SCR-02), `nav-search` (SCR-03), `nav-history` (SCR-06, own) |
| `professional` | `nav-agenda` (SCR-04), `nav-history` (SCR-06, assigned patients) |

| `admin` | `nav-admin` (SCR-07), `nav-audit` (SCR-08) |

navigation is a convenience only: every request is re-authorised server-side.

### 3.3 Client flows

- **Login (SCR-01).** Generate `code_verifier` + S256 `code_challenge` and a
  random `state`, store them in `sessionStorage`; navigate to EP-01. The
  backend serves the standard HTML login form (fields `email`, `password`) and
  redirects to `http://localhost:8080/auth/callback?code=…&state=…`. The
  callback route verifies `state`, calls EP-02, stores the token pair, and
  routes by role.
- **Token policy (RF-23).** Access token (15 min) and refresh token (8 h) are
  kept in memory with the refresh token mirrored in `sessionStorage`; a
  proactive refresh is scheduled shortly before access expiry; a 401 triggers
  one refresh-and-retry, then logout. Logout calls EP-04 and clears storage.
- **Booking (SCR-03).** Search EP-06 → render one `slot-item` per slot → select
  → EP-07. A 409 re-runs EP-06 and shows `error-banner`; success routes to
  SCR-02.
- **Encounter (SCR-05).** Professional opens an `appointment-item` from
  SCR-04/SCR-02 → EP-10 → submits EP-11 → attachments via EP-13.
- **History (SCR-06).** EP-12 returns encounters ordered by `creado_en`; notes
  and diagnosis are rendered as text (never `dangerouslySetInnerHTML`).

## 4. Cross-cutting backend design

- **Error envelope.** A global exception filter maps every failure to
  `{ "error": { "code", "message" } }` with a stable machine code
  (`validation_error`, `unauthorized`, `forbidden`, `not_found`, `conflict`,
  `payload_too_large`, `unsupported_media_type`, `rate_limited`,
  `internal_error`). Stack traces, SQL and paths never reach the client; the
  full error is logged server-side only.
- **Validation.** DTOs with a strict schema (class-validator / Zod pipe,
  `whitelist` + `forbidNonWhitelisted`) reject undeclared fields with 422 on
  every endpoint (RF-12).
- **Authentication.** Access tokens are short-lived signed JWTs (subject =
  user id, roles, scope); refresh tokens are opaque, stored hashed with
  `expires_at` and `revoked_at`, rotated on use. A guard rejects missing,
  expired and revoked tokens (RF-08).
- **Authorization.** `RolesGuard` checks the required role, then a per-resource
  ownership/assignment check runs in the query itself (`WHERE paciente_id = $1`,
  `EXISTS (SELECT 1 FROM cita … )` for professional assignment), so RF-10 holds
  even if a route is misconfigured.
- **Booking transaction (RF-13).** EP-07 opens a transaction, takes
  `SELECT … FOR UPDATE` on the availability row (or `INSERT … ON CONFLICT DO
  NOTHING` against the partial unique index), inserts the `cita`, commits.
  Concurrent duplicates surface as unique violation → 409.
- **Rate limiting (RF-14).** In-memory/sliding-window guard keyed by IP for
  EP-01..EP-04 (5/min) and by user for EP-07 (10/min); 429 with `Retry-After`.
- **Audit (RF-15).** An interceptor writes one `auditoria` row per write and
  per clinical read (EP-10..EP-14), with actor, action, resource type/id and
  timestamp; inserts are non-blocking for the response but failures are logged.
- **Attachments (RF-17).** Multer memory/disk storage outside `public/`,
  server-generated sanitized filename, MIME + size checks before persisting.
- **Health (EP-20).** Liveness only; migrations/seed run before the HTTP
  listener opens, so a 200 implies a usable schema.

## 5. Repository layout

```
/                         docker-compose.yml, .env.example, package.json,
                          playwright.config.ts, README.md
docs/                     architecture.md
backend/                  NestJS app + Dockerfile
  src/main.ts             bootstrap: pipes, filters, guards, rate limit
  src/app.module.ts
  src/common/             error envelope filter, validation pipe, guards,
                          rate limiting, audit interceptor
  src/database/
    migrations/           versioned migrations, each with up and down
    seed/                 deterministic seed (RF-05), idempotent
  src/auth/               EP-01..EP-04, PKCE, tokens, login form
  src/appointments/       EP-05, EP-07, EP-08, EP-10, EP-11
  src/availability/       EP-06, EP-09
  src/encounters/         EP-12, EP-13, EP-14
  src/admin/              EP-15..EP-19
  src/audit/              audit writing/query support
  src/health/             EP-20
  test/                   Vitest unit tests (*.spec.ts)
frontend/                 React + Vite SPA + Dockerfile (static build)
  src/api/                API client and error envelope handling
  src/auth/               OAuth PKCE client and token policy
  src/routes/             protected routing per role
  src/screens/            one file per screen, SCR-01 .. SCR-08
  src/components/         shared UI, including loading/error/empty states
e2e/                      Playwright tests, using the data-testid contract
```
